MeghDrishti — Fresh Project Product Requirements
Version 1.0 | 9 October 2026 | Standalone specification for a new project
We will use Google Stitch as the source of the frontend visual design and screen exports. Claude will convert or integrate those exports into a working React application and implement the interactions, simulation and backend connections described here. Stitch is not the risk engine, database or climate-data provider. Start from a new project. This document contains the complete product requirements; no earlier conversation, prompt, draft or code is required. Build the evaluator demo first; keep the interfaces ready for verified data and services without claiming they are already connected.
1 Product purpose and audience
Primary users are portfolio analysts and fund managers; investment risk teams are secondary professional users. Corporate operations teams may benefit from the same dependency evidence, but supplier procurement is not the main MVP workflow. Different holdings can depend on the same supplier, commodity, route or region. MeghDrishti exposes that concentration, traces modeled disruption and helps an analyst compare responses. It does not guarantee loss prevention or recommend trades.
The distinguishing workflow is automatic location screening followed by evidence-backed portfolio dependency paths, shared concentration and controlled comparisons. A company replacing a supplier does not eliminate the analyst's need to inspect shared dependencies across other holdings. Record an evidenced change and rerun the portfolio analysis rather than asserting that mitigations already occurred.
2 Problem statement and core requirements
Climate risk can propagate through relationships between companies, suppliers, commodities, logistics networks, financial institutions and geographic regions. Portfolio-level assessment therefore requires more than identifying the direct location of a company's assets.
Expected solution: construct a dynamic graph connecting company, facility, supplier, transport route, commodity, region, climate hazard and financial exposure; simulate second- and third-order effects and identify hidden climate exposures across an investment portfolio.
R01. Build MeghDrishti from scratch for investment portfolio analysts, with a functional demonstration before live-service integration.
R02. Automatically screen supported operating locations; offer optional what-if scenarios and separate long-term climate context.
R03. Use Stitch for all frontend visual design, React JS/Tailwind for implementation, React Flow for the graph, Recharts for analytics and Leaflet for geographic maps.
R04. Use Supabase Auth/Postgres for configured persistence, with FastAPI/Python/NetworkX as the authoritative integrated analysis engine. pandas/NumPy support data processing. Gemini provides optional grounded explanations.
R05. Treat missing weather, locations, dependency shares and evidence as unknown. Headquarters and listing country must not substitute for factories.
R06. Label synthetic fixtures, assumptions, dataset-reported links and sourced observations separately. Do not invent real suppliers, routes, financial accuracy or confidence percentages.
R07. Show unique connected investment value and an explicitly assumed stress-weighted exposure metric; neither is a validated prediction of stock-price loss.
R08. Trace up to three commercial dependency connections using strongest simple paths. Prevent cycles, repeated nodes and duplicated financial exposure.
R09. Implement near-term heat screening first. Rain and wind are weather context; automatic flood/drought/cyclone analysis requires additional supported hazard models.
R10. Preserve the supplied climate projection periods and scenarios. Do not convert annual climatology into exact-date weather predictions.
R11. Run the installed synthetic demo without credentials. Clearly indicate which live services, authentication and map resources require configuration or connectivity.
R12. Use the reproducible synthetic reference fixture in section 9 to verify arithmetic, route mapping and browser/backend parity.
R13. Make every page operational, including empty, loading, partial-data and failure states; report implementation status and measured performance honestly.
3 Delivery scope and feasibility
Phase A is a frontend-first evaluator MVP with synthetic fixtures and a deterministic browser engine. No Supabase credentials, Python server or live climate feed is required to use it. It includes a typed operational graph, functional asset/route shock mapping, three commercial hops, provenance, portfolio editing, exposure results and comparison. Optional authentication screens are designed now but disabled when no Supabase is configured.
Phase B connects a small sourced operational subset, raw Sectivia relationships, Supabase Auth/Postgres, Open-Meteo weather and an authoritative Python/FastAPI/NetworkX engine. World Bank projections appear in a separate future-context view. Gemini is optional and does not block results. Extend the dataset after a valid subset works.
A demonstrable Phase A is a reasonable short hackathon scope. A fully sourced, calibrated and validated investment-loss platform is not a 24-hour commitment. Real company relationships require separate operational enrichment before location-level modeling. No custom model training is required for this mechanism.

6 State and mode rules
State machine: no_portfolio -> portfolio_review -> ready -> analyzing -> results or failed. Input changes mark an existing result outdated; do not silently replace an exported run. Live runs use draft_revision/request_id; discard responses for an older revision. Disable double submit, cancel obsolete calls and show pending state. Keep analysis calculations out of React render side effects.
Modes: demo and sourced. Mode is chosen by the available adapter/configuration, not a fake switch that relabels fixtures. Demo includes synthetic regions/events and optional manual overlays. Sourced mode reports imported relationship coverage separately from modeled operational coverage. If live weather fails, cached sourced readings may be shown with original timestamps. If no cache exists, mark unavailable. Never substitute synthetic weather under a sourced badge.
Browser demo can save a bounded run history and restore validated inputs. Handle localStorage denial/quota/corruption with an inline message and in-memory fallback. No authenticated portfolio cache in a shared browser without an explicit retention choice.
7 Normalized data contracts
All evidence-bearing records carry provenance (synthetic, dataset_reported, sourced, assumed, unknown), evidenceIds[], missingFields[] and datasetVersion. Confidence is not a calibrated probability. Freshness belongs to observation/source records, not an arbitrary node score.
Company: id, externalId, name, ticker|null, exchange|null, sectorId, countryOfRegistration|null, roles[]. Supplier is a role of Company; no duplicate supplier node for the same business.
Region: id, name, countryISO3, geographyLevel, providerGeographyId|null, boundary|null, centroid|null. A country registration value does not establish operating location.
Facility: id, companyId, name, facilityType, regionId|null, latitude|null, longitude|null, locationPrecision, operatingRelationship, operationalShare|null, vulnerabilityByHazard|null. Unsupported coordinates remain null.
TransportRoute: id, name, mode, waypointIds[], geometry|null, regionIds[], operatingStatus|null. Waypoint: id, regionId, coordinates|null, role. CompanyRouteUsage: id, companyId, routeId, shipmentShare|null, substitutability|null, evidenceIds[]. No nearest-port inference.
Commodity: id, name, category|null. SupplyItem: id, supplierId, customerId, commodityId|null, facilityIds[], routeIds[], evidenceIds[]. It identifies a specific contract/product dependency, not a fabricated global market share.
CommercialEdge: id, supplierCompanyId, customerCompanyId, dependencyWeight|null, weightBasis (measured or assumed), substitutability|null, supplyItemIds[], status/currentAsOf|null. Original Sectivia directions preserved.
GraphEdge: id, sourceId, targetId, kind (operates, located_in, supplies, provides, uses_route, passes_through, exposed_to, holds), commercialHop:boolean. Generic graph weight is forbidden; weight meaning depends on relationship type.
Holding: id, portfolioId, companyId|null, originalInputName, amount, currency, matchingStatus, exclusionReason|null. Store decimal money values in Postgres numeric; round only display, not intermediate math.
Event: id, hazardType, geographicTargets[], affectedEntityIds[], intensity|null, intensityBasis, validStart, validEnd, fetchedAt|null, mode, source/model, datasetVersion. Heat screening event uses a specified transform from weather with units and disclosed thresholds.
Scenario: id, mode, eventIds[], maxCommercialHops, transmissionMultiplier, assumptionOverrides[], futureProjectionQuery|null, modelVersion, datasetVersion.

HoldingResult: companyId, amount, directStress|null, indirectStress|null, totalStress|null, selectedPathIds[], selectedCommercialDepth|null, connected:boolean, connectedAmount, assumedWeightedExposure|null, evidenceStatus, missingFields[].
Evidence: id, sourceName, url|null, retrievedAt|null, documentDate|null, claim, entityIds[], reportedOrVerifiedStatus. Weather: coordinates, gridCoordinates/model where available, variable, unit, value, validTime, fetchedAt, provider. Projection: region/provider ID, geoLevel, collection, variable, unit, scenario, period, product, ensemble/model, percentile, value, baseline, sourceURL, downloadedAt.
8 Graph semantics and functional shock mapping
Render all expected categories, but make their actual roles explicit. Owning/operating facility links locate operational stress. Routes and waypoints connect a documented used transport dependency to users. Commodity nodes describe the supplied item and show shared material dependencies; do not route the same shortage through both direct supply edges and a generic commodity-market loop. Region and hazard nodes map events; holdings connect exposure to capital.
Facility shock: target facility or supported region -> asset stress -> operator/owner using operational share. Route shock: affected route/waypoint -> assumed route availability disruption -> company using shipment share and explicitly assumed replacement capacity. These are initial operational seeds, not commercial hops. Multi-site shares require documented sums; incomplete shares remain unmodeled. Missing mapping/share is unknown in sourced mode unless the analyst enables an explicit assumption overlay.
Commercial shock: supplier stress -> customer through a specific supplies relationship. Future lender/borrower links require loan-book exposures and a separate credit mechanism; do not fabricate these because the source has a finance sector. Financial exposure in MVP is the actual portfolio holding amount. Claims of an investment bank network are deferred until supported data and mechanism exist.
Do not silently normalize inconsistent measured shares. Reject or quarantine totals above one with validation feedback. Explicit user assumption normalization is possible only after preview and acceptance.
9 Simulation specification and reference numbers
All stress numbers lie in [0,1] and represent assumed operational disruption, not probability of default, asset return or measured physical damage. A zero reading is valid only for a supported evaluated input; absence of data is null.
Initial facility seed = event intensity × asset vulnerability × operational share. Initial route seed = event intensity × route vulnerability × shipment share × (1 - assumed replacement fraction). Define these transforms in backend/config/model-defaults.json, with units and rationale, rather than constants in UI components.
Combine overlapping source seeds at a company by maximum for this MVP. Retain all candidate sources. Use the maximum of co-located hazard stresses rather than implying independent joint probabilities. This transparent choice does not capture cumulative effects; compound hazards are later work.
For each seed, enumerate simple supplier-to-customer paths up to three commercial edges. Propagated stress = seed stress × product(edge dependency weight × transmission multiplier). Skip repeated entity IDs within a path. Path identity includes seed and edge IDs, supporting parallel relationships without double counting. Bound traversal to the portfolio analysis subgraph including relevant dependencies through the configured hop limit; report any truncation. Visual filters must never change numerical results. Cache by graph/version, seed inputs, parameter set and overlay, not just portfolio name.
Choose strongest path per company; tie-break by shorter commercial depth then stable path ID. Retain alternatives for inspection. Report selected depth as direct seed/first/second/third commercial connection. Do not imply complete additive decomposition by order. DirectStress is unknown if own operating coverage is insufficient even when indirect stress is available. A high indirect finding with unknown direct exposure is Potential indirect exposure, not proven hidden gap.
Total portfolio capital = all valid holdings in the selected currency. Mapped capital = matched holdings. Modeled capital = holdings with a runnable evidence/assumption path. Connected capital = unique holdings with a supported or explicitly assumed path from the selected affected dependency; zero severity still leaves structural connection visible. Stress-positive connected capital may be separate. Model-weighted exposure = sum(amount × modeled stress) over modeled holdings; display excluded amounts alongside, never silently zero them.
Reference demo: hazard intensity 0.8; supplier facility vulnerability 0.75; operational share 1; initial supplier stress 0.6. Supplier -> Aster dependency 0.6; Aster -> Beacon 0.5; Beacon -> Cedar 0.5; transmission 0.7. Aster 0.252, Beacon 0.0882, Cedar 0.03087. Fourth holding Evergreen has no recorded affected path. Holdings ₹40 lakh, ₹30 lakh, ₹20 lakh, ₹10 lakh; total ₹100 lakh; connected capital ₹90 lakh; weighted model metric ₹13.3434 lakh. Move ₹10 lakh from Aster to Evergreen: total unchanged, connected capital ₹80 lakh, weighted metric ₹10.8234 lakh. This does not establish Evergreen as safe.
Add a functional synthetic route shock targeting Delta's logistics use. Use event intensity 0.8, route vulnerability 0.6, shipment share 0.4, replacement fraction 0; seed 0.192. Facility and route candidates combine by max, so the 0.6 facility seed wins when both are selected. Route-only scenario must still propagate and produce a different valid result. Commodity panel traces electronic components through the same supply-item IDs without creating a second numerical channel. Include a cyclic alternative edge to verify no revisits; keep cycle fixture separate from default screenshot values.
10 Weather and future climate integration
Open-Meteo first query: supported operational coordinates, seven-day daily temperature_2m_max; precipitation_sum and wind_gusts_10m_max as context. Additional variables only when used by a visible requirement. Verify current parameters, units/timezone and service terms before shipping. Model/grid readings are not on-site observations. Deduplicate nearby queries only with documented spatial resolution and mapping. Store validTime and fetchedAt.
Initial heat screen may compare temperature to a configured operational screening threshold (for example 35°C as a demo assumption, not universal damage threshold). Default prototype transform: intensity = clip((maximum seven-day forecast daily maximum temperature in °C - 35) / 10, 0, 1), with a screening alert when intensity is positive. Both 35°C threshold and 10°C span are configurable assumptions, not calibrated damage relationships. Display forecast values and transform separately; vulnerability and stress are assumptions. Do not claim rainfall predicts inundation, wind gusts prove cyclone damage, or drought is defined by low annual rainfall alone. Flood/river-level/navigation datasets can be added later with their own mapping model.
Refresh configurable, initially hourly where usage terms permit, with cache reuse, timeout, retry/backoff and provider limits. Credentials server-side where needed. Weather unavailable stays unavailable; stale sourced cache remains sourced and stale. Graph updates occur when inputs change; label model issue/valid/fetch times, not Real time prediction.
World Bank: CMIP6 cmip6-x0.25; annual climatology hd35 and optional tasmax; historical 1995–2014, future 2040–2059; SSP2-4.5 and SSP5-8.5, multi-model median. Optional p10/p90 are climate model spread, not financial confidence bounds. Map provider geography explicitly to actual supported operations; national context is labeled national. Optional rx5day/r50mm are precipitation indicators, not flood losses. Keep units and product metadata. Do not blend annual hot-day counts with next-week temperatures or quietly substitute another API/pathway when files are absent.
Future-context view shows indicators and exposure connections. Future operational-stress transforms remain explicitly assumed scenarios, separated from the raw projection. No automatic stock-loss projection or exact-year event probability.
11 Supabase and backend contracts
Demo uses MockRepository and BrowserSimulationService. Sourced mode uses SupabaseRepository and FastApiSimulationService. Shared JSON schemas and golden fixtures govern parity. UI never chooses an engine based on an unverified label. Secrets and authoritative numeric logic remain server-side after integration.
Supabase tables: dataset_versions, companies, regions, facilities, routes, route_waypoints, commodities, supply_items, relationships, route_usage, evidence, weather_observations, climate_projections, portfolios, holdings, analysis_runs, analysis_results, assumption_overlays. Keep demo tenant/data separate from sourced namespace. User-created portfolios/runs/overlays owner_id references auth.users. Every child access policy checks the parent owner; never trust owner_id supplied by a browser. Public operational data is read-only to clients; import/update privilege restricted to server/admin. Private API reads and exports authorize run ownership.
API v1 routes: GET /datasets and /graph?portfolioId; POST /portfolio/match and /portfolio/validate; GET /events?portfolioId; POST /analysis; GET /runs/{id}; POST /compare; POST /runs/{id}/explanation. Optional later admin POST /data/refresh cannot be public. Pagination/filtering for large graphs; schemaVersion in payload. Analysis input includes holdings/scenario/overlay references plus expected dataset/model versions. Response includes runId, requestId, mode, status, results, coverage, warnings and inputHash. Error object includes code, message, fieldErrors and retryable.
Validate Supabase JWT server-side using configured issuer/audience/current signing keys. Bind database operations to the authenticated identity or explicit owner checks; a server service-role key bypasses RLS and must not be used as a substitute for authorization. Set exact allowed frontend origins. Timeouts and retry only safe/idempotent operations; idempotency key for creating runs. Serialize request snapshots and discard stale UI responses.
Gemini receives sanitized computed results, evidence IDs and assumptions, not raw private holdings by default. Structured output: summary, affectedPaths with existing path IDs, limitations, analystChecks. Validate references and numbers; reject invented entities. Prompt injection in imported names/source documents is untrusted input. Deterministic explanation fallback always available. Never let generated text modify authoritative result metrics or execute actions.
12 Raw dataset and import rules
Store raw Sectivia originals under backend/data/raw/sectivia read-only. Compute hashes before/after import. Preserve every line, column value, ID, name, blank and ordering; all enrichment lives in separate records. Prefer JSON as one base import, or CSV pairs with consistent ID joins. Loading both must not duplicate edges. Namespace original IDs; synthetic IDs never override sourced records.
The published Sectivia reference describes 215 companies and 350 relationships; validate actual counts when the files are provided. Treat source datasets as inputs supplied later, not files already present in the new project. The basic company/relationship schema does not establish facility coordinates, route usage, vulnerability, dependency shares or portfolio holdings. Do not assume every link has supporting URL just because fields exist. Inspect current schema and emit an import report: counts, duplicate/reference validation, unmapped fields and evidence gaps. No changes to raw source to fill missing values.
Enrichment arrays/tables: facilities, regions, routes/waypoints, companyRouteUsage, supplyItems, relationshipEvidence and assumptionOverlays. A real supplier relationship does not identify which supplier factory serves the customer. Link specific sites only with evidence. Attribute Sectivia CC BY 4.0. Keep source license notes and dates for every feed.
CSV holdings upload uses stable IDs/ticker+exchange then exact aliases, followed by human review for ambiguity. Name fuzzy matching suggests candidates only. Accept zero, reject negative/blank/nonfinite amounts; combine duplicate company IDs. Phase A uses INR only, rejects mixed currencies. Later FX requires dated rate source and conversion snapshot, not a label switch.

14 Security reliability and edge cases
Bound CSV file size/rows, reject malformed quoting through parser errors, validate referential integrity and avoid arbitrary upload code execution. Use URL schemes allowlist for evidence links; render text rather than injected HTML. CSV export prefixes/escapes cells beginning with spreadsheet formula characters; JSON exports include exclusions and provenance.
Empty portfolio: no analysis, guided action. Missing company/coords/hazard/share: unknown with exact excluded amount. Several facilities: incomplete shares displayed, no forced total. Unknown route geometry: list only. Disconnected holding: no recorded path. Dataset mode switch: confirm discarding only unsaved user edits or preserve drafts separately. Currency disagreement: block. Cycles: simple path check. Large network: affected subgraph and explicit traversal bounds. Import failures: transactional dataset version remains unchanged. Explanations disabled: deterministic narrative. Auth expiry: refresh/relogin without discarding draft. Denied local storage: in-memory fallback. Cached weather: original timestamp and stale label. Unsupported future period: no extrapolation/clamping disguised as a request result.
